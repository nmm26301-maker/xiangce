# FlipYear 相册书 · 2.2.0

安卓本地年度照片书的个人实现。黑色书房背景、年度转盘、照片封面、十二个月的日历纸张和卷页动画。

## 使用

1. 保留旧版应用，直接安装 FlipYear-v2.2.0.apk。包名与开发签名沿用 1.0，首次启动会迁移旧版相册。
2. 点击「连接系统相册」，由系统选择照片与视频的授权范围。可授权全部、部分或只授权一类；拒绝后仍可手动制作照片相册。
3. 选择年份，翻开封面，滑动或用按钮翻阅月份；横屏/宽屏显示双页。
4. 点日期查看完整比例的照片或视频封面，用「查看本月影像」进入列表；视频需再点「播放视频」打开原生播放器。年度封面可选择照片或视频封面。
5. 「相册」中创建主题照片书，可编辑文案、日期、顺序、页面样式，导入或删除照片。
6. 「今日」显示往年同月同日的照片；「偏好」提供浅/深色、减少动效、翻页速度、备份、桌面小组件与开源许可。

## 桌面小组件

- 「偏好 → 添加桌面小组件」请求桌面确认；不支持快捷添加时，长按桌面 → 小组件 → FlipYear 桌面回忆。取消添加不会显示成功提示。
- 点小组件右上角齿轮，可为每个实例分别选择「那年今日」或「固定照片」。默认完整呈现照片，可切换填满画框。支持调整大小。
- 那年今日仅查询已授权的系统照片，使用真实拍摄日期匹配往年同月同日，不用入库日期替代；无匹配时显示空状态。按拍摄时间排序，最多轮阅 128 张。多张时点「换图」浏览。
- 固定照片使用系统文件选择器的持久 URI 授权，不要求开放整个照片库。源文件删除或授权撤回后显示不可用；替换、取消选图和移除组件会清理不再使用的持久授权，多组件共享的授权保留。
- 点照片在应用中按完整比例查看。点 ↻ 手动刷新；系统约每 30 分钟请求更新，打开应用、相册变化和授权结果也会刷新。受系统省电和桌面实现影响，定时更新可能延迟，不承诺零点立即更新。
- 单个小组件位图长边不超过 400px，按宿主尺寸收缩；整组 RemoteViews 替换，避免累积位图动作。没有额外后台服务、精确闹钟或网络依赖。照片会显示在桌面，请按自己的隐私偏好设置。

## 系统视频

- 连接系统相册后，视频与照片按拍摄日期共同生成年鉴。「今日」也可查看往年同日的视频，日历与列表标注 ▶ 和时长；不自动播放。
- 预览中点「播放视频」打开应用内原生播放器，支持系统播放／暂停及进度拖动，保持画面比例。横竖屏保留同一播放器；切入后台暂停并在停止时释放，返回后保持暂停、恢复位置。
- 视频只保存 MediaStore 引用与元数据，按需生成封面，不把原视频读为 base64，也不转码或修改原文件。预览封面最多 640px，日历／列表按需使用 320px 缩略图。Android 8.0 使用系统小尺寸缩略图，8.1 起使用缩放帧提取。
- 播放仅接收本地 MediaStore 数字 ID，不接受任意文件路径或网络网址；打开前由系统重新检查文件授权。封面提取失败时仍可尝试播放，播放器对缺失文件、撤回授权和不支持的编码显示错误。
- 实际编码支持取决于设备系统，未额外捆绑解码器。尚未在安卓设备验证实际解码、音频焦点、暂停拖动及后台恢复。
- 本版视频范围是系统年鉴／今日回忆。主题相册导入、JSON 备份和桌面小组件继续只处理静态照片；网页版不播放系统视频。Live Photo／Motion Photo 配对和动态照片还原未实现。

## 照片与日期

- 系统年鉴只保存 MediaStore 索引，预览按需在手机上生成；不复制整套原始照片、不上传。
- 系统照片与视频增删变化会触发索引刷新；回到前台会重新核对已有索引，覆盖部分授权范围改变但权限枚举不变的情况，也可手动重新扫描。
- 优先使用拍摄日期；系统缺失该时间时按入库时间归档，并在首页显示数量。两个时间都缺失时不伪造日期。
- 手动导入优先读取系统/EXIF 日期，其次识别文件名中的 YYYYMMDD 或 YYYY-MM-DD 日期。无法确认时留空，可在编辑页填写。
- 自建相册导入图片会转换为长边最多 1600px 的 JPEG；系统照片预览也最多 1600px。手机原始照片不修改。
- 月历缩略图会裁成单元格形状，完整照片预览采用 contain，不裁切边缘。
- 视频使用独立类型和 ID，避免与相同编号的照片混淆；无有效日期的系统影像不会伪造日期加入年鉴，首页显示数量。Live Photo 和自动挑选最佳照片未实现。

## 备份与升级

自建相册使用 IndexedDB 保存，可导出 JSON 并恢复为新相册。系统年鉴引用手机原图，源照片删除、授权收回或设备更换后需要重新连接，不包含在自建相册备份中；请用系统相册的备份功能保管原图。

v1 的 file origin 数据通过同源迁移页读取，先写入应用私有临时备份，再交给 v2 本地 HTTPS origin 的 IndexedDB。只有新数据库写入成功才清理临时备份。未修改 v1 原数据库。迁移失败会提示并保留数据；不要先卸载旧版。

开发版沿用同一签名证书 SHA-256 相同：bc1f2cbc5fbfd8a72b23d7517135eb507f89c45b861ba0da2410b060a75e4ab7。

## 安卓与构建

- minSdk 26 / Android 8.0，targetSdk 34，compileSdk 35；建议更新 Android System WebView。
- 申请 READ_MEDIA_IMAGES、READ_MEDIA_VIDEO、Android 14 部分照片与视频权限及旧系统 READ_EXTERNAL_STORAGE；只有点击连接相册时才申请。手动选图仍使用系统文件选择器。
- 不申请 INTERNET、管理所有文件或定位权限。https://flipyear.local 是 WebView 内部拦截的本地资源路径，不访问服务器。
- Android Studio：JDK 17、AGP 8.7.3、Gradle 8.9、SDK 35；工程无 Gradle Wrapper，可使用本机配置。
- Linux SDK 构建：设置 ANDROID_HOME，执行 bash build-android.sh。可用 ANDROID_BUILD_TOOLS / ANDROID_JAR 指定 SDK 路径。
- signing/flipyear-debug.jks 是开发版调试签名，别名 androiddebugkey，标准调试口令 android。只用于开发版覆盖安装。

主要源码：app/src/main/assets/index.html、yearbook.js、yearbook.css；安卓容器 MainActivity.java、MediaLibrary.java；原生小组件 MemoryWidget.java、WidgetConfigActivity.java；共享图片预览 PhotoDecoder.java、系统视频播放 VideoPlayerActivity.java、媒体授权规则 MediaPolicy.java。

`python3 scripts/build-web.py` 生成自包含 FlipYear.html；网页版可手动导入，系统照片库连接仅在 APK 中可用。网页版与 APK 本地数据独立，可用自建相册备份迁移。

## 开源与验证

翻页采用固定版本 @gullabs/flipbook-core 3.2.2（MPL-2.0），无运行时依赖。对应源码和许可证见 third_party/flipbook-core；方案比较、维护状态、限制和来源见 SOURCE-REVIEW.md。

Node + Playwright + Chromium 环境下执行：

```bash
node tests/functional.cjs
node tests/yearbook.cjs
node tests/widgets.cjs
node tests/videos.cjs
bash tests/native-policy.sh
```

可通过 CHROME_BIN 指定浏览器。测试涵盖编辑、持久化、备份/恢复、月历闰年、卷页正反向、快慢触摸、宽屏双页、旧状态迁移、部分授权回调及小组件桥接入口。原生策略在 JVM 验证闰年、本地时区、夏令时边界、照片切换、位图预算、分类型授权及视频 ID。视频测试覆盖混合索引、时长标记、主动播放入口、封面失败、权限回滚与非法 ID。APK 编译、对齐、签名校验通过；浏览器原生传输使用 mock，尚未在安卓真机或模拟器安装验证桌面宿主、持久 URI 授权、权限对话框、MediaStore 和 WebView。

尚未提供回忆通知、云同步和 PDF/视频导出。

项目仓库：https://github.com/nmm26301-maker/xiangce 。源码、开发签名、测试记录和安装包在该仓库维护。安装包位于 releases/FlipYear-v2.2.0.apk。
